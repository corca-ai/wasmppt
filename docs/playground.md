# Browser Dogfood Playground

The public [wasmppt playground](https://corca-ai.github.io/wasmppt/) is the smallest end-to-end
consumer of Generation API v1. It is a static GitHub Pages application: no presentation or image
is uploaded to a server.

## Workflow

The page loads the scalar Wasm module in a module Worker. A user can keep the bundled report POTX
or select a local POTX, POTM, or PPTX. Compile transfers the file into the Worker and renders the
returned binding descriptors and diagnostics. Generate encodes text, image, table, slide-copy, and
chart data into the binary injection payload, consumes the pull stream, and downloads a PPTX Blob.

The bundled `fixtures/dogfood/report.potx` deliberately exercises both preferred shape-metadata
bindings and a split workflow with table rows and slide control. Its source is generated by
`write_dogfood_fixture`, recorded in `fixtures/corpus.json`, and covered by the normal corpus hash
gate.

## Build and deployment

Build and test the exact static artifact locally:

```sh
npm run build:wasm-hosts
npm run build:pages
npm run test:pages
```

The CI `pages-dogfood` job downloads the same revision-bound Wasm artifact used by browser,
workerd, and performance gates. It builds the site and runs the Chrome download smoke test.
Successful `main` pushes upload `target/pages`; the dependent `pages-deploy` job publishes that
artifact through GitHub's official Pages workflow.

## Scope

This is a dogfood and compatibility surface, not a hosted document service. It intentionally has
no analytics, persistence, remote template fetch, or server-side generation. Browser memory limits
still apply: applications processing large decks should consume `generateStream` incrementally
instead of collecting every chunk into one Blob as this download-focused example does.
